**Thursday, 20 August** · Local AI infrastructure dominates today, with useful tools but important licence, data and network boundaries.

## Ready to try
**RyanCodrai/turbovec · Try · MIT · Experimental**

A local Rust/Python vector index for retrieval-augmented AI systems constrained by RAM or latency. Start with `pip install turbovec` and a disposable copy of representative embeddings; the index itself has no managed service or network path, but it is pre-1.0 and maintainer-concentrated, untrusted index files are a security surface, and its speed and retrieval-quality results are project-run rather than independently reproduced.

[Open repository ↗](https://github.com/RyanCodrai/turbovec)

## Test carefully
**Tencent/AI-Infra-Guard · Test carefully · Apache-2.0 file / extra attribution stated · Maturing**

Scans live AI services, Model Context Protocol servers and agent skills for known vulnerabilities and risky behaviour, for authorised security testing. Trial the standalone skill scanner on a safe test repository or run Docker on loopback; the web UI has no user authentication, active probes require target permission, and scanned content should be treated as leaving the host whenever its configured model service is external; benchmark results remain project-claimed.

[Open repository ↗](https://github.com/Tencent/AI-Infra-Guard)

**modular/modular · Test carefully · Apache-2.0 with LLVM exceptions / MAX Community License · Maturing**

Open-source Mojo and MAX components provide AI kernels, model pipelines and an OpenAI-compatible inference server for performance engineers. Use `pixi` or `uv` with a small supported model on a Linux GPU host; model downloads and licences vary, hardware needs rise quickly, and the quickstart server binds all interfaces without meaningful authentication, so keep it private or add a hardened front end.

[Open repository ↗](https://github.com/modular/modular)

**PostHog/posthog · Test carefully · MIT core / proprietary enterprise code · Mature core, beta AI**

Combines language-model tracing with product analytics and beta agents that turn errors and usage signals into reports or draft pull requests. Product teams can trial the cloud tier with synthetic traces and a throwaway repository; prompts, responses, tools and user context then reach PostHog, every code change needs review, self-driving pull requests cost $15 after the first three each month, and self-hosting is an unsupported single-machine hobby deployment.

[Open repository ↗](https://github.com/PostHog/posthog)

**JuliusBrussee/caveman · Test carefully · MIT surfaces / BSL-1.1 core · Experimental**

Compresses coding-agent context and replies through an optional skill and local proxy, for developers monitoring token use. Try the MIT skill first in a disposable agent profile; the proxy passes provider credentials and traffic, stores exact originals in unencrypted local SQLite, and enables content-free telemetry by default, while the useful engine is source-available rather than open source and its headline savings are project-benchmarked.

[Open repository ↗](https://github.com/JuliusBrussee/caveman)

## Watch
**agent-substrate/substrate · Watch · Apache-2.0 · Experimental**

Multiplexes many stateful agents across fewer Kubernetes workers using gVisor or lightweight virtual-machine sandboxes, aimed at infrastructure teams rather than agent builders. Reproduce only the counter demo on a local `kind` cluster: setup needs Go, Docker, `kubectl` and cluster-level scripts, snapshots and routing create cross-actor security boundaries, and maintainers explicitly say it is not production-ready and its APIs will change.

[Open repository ↗](https://github.com/agent-substrate/substrate)
