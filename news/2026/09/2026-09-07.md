## AI News Brief
**Monday, 7 September** · Local-model workflows broaden, while agent runtimes add consequential controls and defaults.

## 🧠 Models & Platforms
**iFlytek releases Spark X2.5 for coding and agents**

iFlytek released a 293B-A30B mixture-of-experts model on its open platform, saying it improves coding, agent, maths and general-understanding tasks on a domestic compute stack. The capability claims are vendor-reported; developers gain another API option, not independent proof of performance.

[Direct source ↗](https://www.jiemian.com/article/15062144.html)

**OpenAI says coding agents have reached its “research intern” target**

OpenAI says an internal system can now complete well-defined research tasks that would take a skilled researcher a few days; it also reports 3.1 agent-workdays for every human workday across its research organisation. The measurements are preliminary, internal and not a public product release, but they signal increasingly agent-driven frontier-model R&D.

[Direct source ↗](https://openai.com/index/research-acceleration-view-inside-openai/)

## 🛠 Agents, Tools & Open Source
**Ollama previews local-model access inside ChatGPT Desktop**

Ollama’s 0.34 release candidate lets its macOS app expose local open models directly inside ChatGPT Desktop; it also adds OpenAI-compatible tool search and response compaction. This is pre-release software, so test separately rather than treating the integration as production-ready.

[Direct source ↗](https://github.com/ollama/ollama/releases/tag/v0.34.0-rc1)

**OpenClaw 2026.9.2 enables swarms by default**

The open-source agent platform now enables concurrent swarms by default, supports GPT-6 Astra and recovers active, queued and delegated replies after gateway restarts. Existing operators should review `tools.sessions.visibility`: ordinary cross-agent session access now defaults to all sessions unless narrowed to `agent` or `self`.

[Direct source ↗](https://github.com/openclaw/openclaw/releases/tag/v2026.9.2)

**LiteLLM 1.100 hardens credentials and RAG uploads**

Version 1.100 adds security controls to `/v1/rag/ingest` and fixes cases that could pass a caller’s virtual key through Vertex routes or copy forwarded credentials into retry breadcrumbs. Shared-gateway and RAG operators should upgrade and review their configuration; the release notes do not label these fixes as CVEs.

[Direct source ↗](https://github.com/BerriAI/litellm/releases/tag/v1.100.0)
