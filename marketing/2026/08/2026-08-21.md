## 📡 Marketing Signals

**Google Ads · Multi-campaign AI Max experiments arrive in September · Test**
Google is adding A/B tests for budget and ROI-target changes across multiple Search campaigns, while allowing AI Max tests to retain brand and location controls. Define holdouts, decision thresholds and change approval now; treat Performance Planner’s one-click apply as a reviewed action, not automation.

**Evidence:** Confirmed rollout; projected performance is platform-claimed and not an incrementality result.  
[Direct source ↗](https://blog.google/products/ads-commerce/ai-max-testing-planning-tools/)

**Apple EU apps · New payment and distribution terms start 1 October · Act**
Attachment 14 replaces earlier EU addenda and sets 12-month payment-route elections plus commissions for alternative processing, linked offers and alternative distribution. App and commerce teams should model margin, attribution, reporting and checkout UX before accepting; the approaching effective date makes this slower rollout actionable now.

**Evidence:** Confirmed Apple contract terms; commercial outcomes are untested and the agreement needs legal review.  
[Direct source ↗](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/#A14)

## 🛠 Marketing Tool Radar

**umami-software/umami · Test carefully · MIT · Mature**
v3.3.1 hardens 2FA configuration, fixes event-property filtering and preserves zero/false values plus events missing session records—changes that can alter both access and reported results. Upgrade a database backup in staging, then reconcile one site’s events and funnels before production.

**Evidence:** Project release, documentation and inspected MIT licence; the upgrade and analytics fixes were not independently tested.  
**Boundary:** Self-hosting keeps analytics in the chosen PostgreSQL instance, but the sample Compose exposes port 3000 and uses placeholder/default secrets. Replace them, change the initial admin password, add TLS/private networking, set the 2FA key and review the username-lowercase migration.  
[Open repository ↗](https://github.com/umami-software/umami/releases/tag/v3.3.1)

**logly/mureo · Test carefully · Apache-2.0 · Beta, high-churn**
v0.13.0 gives whole-workspace collection failures a distinct state, shows report-specific metrics that were previously invisible and fixes six report types that shipped skills told agents to write but the tool rejected. Trial the synthetic scenario or read-only BYOD mode and verify failure-state and report rendering before trusting conclusions.

**Evidence:** Project release, documentation, security policy and inspected Apache-2.0 licence; no live-account test was run.  
**Boundary:** Python 3.10+ and an agent host are required. BYOD stays local and read-only, while live mode stores platform credentials and can mutate ad accounts; the security policy still names 0.10.x as supported although 0.13.0 is current.  
[Open repository ↗](https://github.com/logly/mureo/releases/tag/v0.13.0)
