## Routing

| Material | Route |
|---|---|
| Time-bound or edition-specific | Keep only in the dated briefing archive. |
| Reusable for a person, but not agent-executable | Create one canonical Markdown guide and link it here. |
| Repeatable agent procedure with real tests | Publish under `library/skills/<skill-name>/SKILL.md` and link it here. |
| Duplicative, weakly evidenced, promotional, or private | Do not promote it. |

A creator calling something a “skill” does not make it one. A public skill needs clear triggers, inputs, executable steps, failure behavior, provenance, and a verification path. Otherwise, it remains a guide.

## Library law

- Keep one canonical file for each artifact; the Library links to it rather than copying the body.
- Preserve public sources, evidence status, limitations, and last-reviewed dates.
- Commit the artifact, index update, and ledger row atomically; treat the row as valid only after all public URLs are readable and verified.
- Never expose private ingestion records, receipts, internal IDs, client material, credentials, or local paths.
- Do not force every briefing item to produce a durable artifact.
